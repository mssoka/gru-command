## Round 2 blocker follow-up

The r2 review of `4aa449b65392b211c28815de05ac411f00e0cddf` identified one new blocker: **Directory replacement lets unrelated hunks satisfy renamed-caller proof**. A literal pathspec on the former caller file name can also select a newly added descendant after the former file becomes a directory. The selected rename now diffs the exact prior and target *regular blob IDs* returned by the frozen trees, not a pathspec that can include descendants. The same bounded patch is used by the lead tool and submission validator, with `--text --no-textconv --no-ext-diff` preserving attribute independence. `rejects an unrelated descendant hunk after an unchanged caller is renamed` reproduces the false acceptance before the change and rejects it after; `accepts only the caller hunk when an edited rename also replaces its old path with a directory` checks genuine edited-rename proof under checkout-local attributes. The r2 report remains archived and unchanged. Its separate nonblocking warnings are not declared cleared by this scoped blocker fix.
